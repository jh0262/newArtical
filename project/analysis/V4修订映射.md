## 四、根据实际结果选择结论措辞

| 实际证据 | 正文可用的结论方向 |
|---|---|
| 完整PADE在同父家族校正后若干题显著更优 | “在相同实际FE下，新增状态与几何干预在这些问题上提供了可分辨的增量收益”，列实际胜/未显著/负及效应 |
| 相对经典DE更好，但对同父多未显著 | “完整配置具有竞争力；其优势中包含精英引导、归档和参数学习的作用”，新增机制按消融结果分别说明 |
| 某机制家族出现混合/负效应 | 明确地形或工程条件及不利效应，讨论门和动作的适用性；保留其他成立的贡献，不改冻结参数追求阳性 |
| 某P组未触发或很少触发 | “在本组预算和状态轨迹下P未/少进入活动”，其性能差异不能归因于大量脉冲恢复；以门日志说明 |
| PV的J存在校正后正效应且确有规格变化 | 将J的目标/可行性效应与有效网格变更、接受量共同解释，严格区别P内网格动作 |
| WB/CB差值仅达浮点末位 | 解释数值终值与重复性，不换算成制造节材收益；整体统计结果照实保留 |

## 五、构建脚本集成注意点

v3的`analysis/build_manuscript.py`可复用OfficeCLI段落、原生公式、表与图的构建函数，但应先复制到v4目录并改ROOT、SOURCE、OUT和输出日志路径。脚本在构建计划阶段即写`manuscript_text.txt`与`bibliography_map.json`；不要直接重跑原脚本以免覆盖v3说明或复建旧稿。

主要旧生成位置：§1.5在144—146行；§2在148—210行；旧设置和T1在212—230行；图2及T2在231—245行；工程模型/旧表在246—292行；工程综合图在293—296行；结论从298行开始。构建器会重排引文，内部参考号不能直接当成交付Word当前号。

新替换稿含LaTeX记号，不宜整段交给旧`md_body→p→clean`作为普通文本，否则可能残留控制串或损失上下标。独立显示式通过`eq()`生成OMML；行内用正确Unicode或明确的原生数学对象。最后检查版式时同时核对行/列向量乘序、根号、FE门中的严格不等号及统计表方向。
